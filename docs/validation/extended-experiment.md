# Extended experiment validation

## Implementation checks

Both the main repository and the local Zenodo mirror pass the full analysis
suite: 30 tests, including exact typed MVT multisets, real Rust v1/v2 round trips,
all five variants, source-ID counts, exact integer byte storage and additive
matched-block decomposition. The host skips one GDAL test; that test passes in
both separately built Docker images.

Both converters' focused GDAL, protocol, source-fidelity and pipeline-default
suites pass all 28 tests. Collecting the entire historical main converter suite still
fails in `test_metric_registry.py` and `test_render_results.py`, which import
`CONVERSION_METRICS` and `render_rows` from the unchanged `src.results` module.
These unrelated collection errors are not reported as a full-suite pass.

Both final Docker images pass a real Rust v1/v2 conversion and round trip, exact
MVT aggregation, and the GDAL provenance test. The latter checks disjoint FIDs,
byte-identical geometry/attributes, and remapped RTree entries. Images use
`maplibre-tiles 0.4.1` source with `mlt-core 0.22.1`, as recorded in their build
manifests; the primary corpus uses the single Windows Rust build recorded in
[extended-run-environment.json](extended-run-environment.json).

During generation Docker reported 16,710,705,152 bytes of VM memory and four
logical CPUs. The API container had no explicit memory/swap quota and was not
OOM-killed at the observation point. This is configuration evidence, not a peak
RSS benchmark. The native per-tile budget is separately set to 256 MiB.

The largest new Dense-16 MVT from each dataset passes v1/v2 conversion and native
round-trip verification at 256 MiB. PDOK first exposed a separate 32 MiB Buffa
element-memory limit during MVT import; increasing only the MLT budget to
512/1024 MiB did not change that error. The corrected adapter explicitly passes
the budget into the MVT reader as well. Before/after evidence is recorded in
`extended-max-dense16-budget-before-mvt-fix.json` and
`extended-max-dense16-budget.json`. A regression test rejects a synthetic MVT
at the input stage with 1 MiB and accepts it at 256 MiB. A real-tile comparison
confirms identical encoded v1/v2 bytes before and after this budget-only patch.

## Full-corpus acceptance

The regenerated corpus passed acceptance: **75 archives**, **45,689 MVT addresses**,
**91,378 verified MLT addresses** across both versions,
and **0 round-trip differences**. All
**9,042 aggregate blocks** passed exact typed-multiset verification.
Independent readback verified the measured addresses and payload bytes in all
75 physical archives. Main and Zenodo unrounded CSV exports match byte for byte;
both actual manuscript PDFs compiled, and the dataset export checksum list passed.
Executable evidence is generated by `analysis.extended_report` in
[`extended_checks.md`](../data/extended_checks.md) and
[`extended_claims.json`](../data/extended_claims.json). A clean fixture test or a
Docker smoke test does not replace those corpus-wide checks.

Detailed observations use partitioned Zstandard Parquet. SQLite is restricted to
aggregate summaries, compact source-ID lookups and the unchanged source/normalized
inventories. GDAL's temporary MBTiles/GeoPackage files remain in Linux disk scratch
because they are native geospatial formats. See the
[storage and memory explanation](../extended_experiment.md#memory-and-intermediate-storage).

The interrupted host run retained 24 completed groups after checking all 72 archive
hashes. Only the incomplete Natural Earth Standard group was encoded again.
The 30 historical archives and 50 historical analysis files also matched their
saved checksums. Recovery details are in `extended-recovery.json` and the
execution-environment manifest. The complete 30-test analysis suite was rerun
successfully in each repository after recovery (one host GDAL skip each;
the GDAL test passed in both final Docker images).
